# Output Format — v2

What the toolkit generates in a target project.

---

## Directory Structure (After `harness init`)

```
project-root/
├── CLAUDE.md                           ← Map (~20 lines, v2 markers)
├── .harnessignore                      ← Patterns to ignore during discovery
└── .claude/
    ├── settings.json                   ← Claude Code settings (hooks registered here)
    └── harness/
        ├── project-context.json        ← Discovery output (auto-detected + user answers)
        ├── config.json                 ← Toolkit metadata (tier, patterns, version, hashes)
        ├── rules/                      ← Zone A: Toolkit-managed, regenerated on update
        │   ├── conventions.md          ← Overrides-only coding conventions
        │   ├── risk-rules.md           ← Structured safe/risky/blocked command rules
        │   ├── workflow.md             ← Session protocol (standard+ tier)
        │   └── architecture.md         ← Non-obvious arch decisions (full+ tier)
        ├── hooks/                      ← Zone A: Auto-generated hook scripts
        │   ├── pre-command.sh          ← Risk classifier (parsed from risk-rules.md)
        │   └── post-edit.sh            ← Auto-formatter (standard+ tier, if formatter detected)
        ├── state/                      ← Zone B: Agent-managed, never overwritten by toolkit
        │   ├── progress.md             ← Session continuity (what's done, what's next)
        │   ├── learnings.md            ← Discoveries and gotchas
        │   └── plans/                  ← Work plans
        │       ├── _template-feature.md
        │       └── _template-bugfix.md
        └── backup/                     ← Auto-backups (last 5, pruned automatically)
            └── {timestamp}/
```

---

## Zones

### Zone A — Toolkit-Managed

Files in `rules/` and `hooks/`. Toolkit owns these and will overwrite them on `harness update`.

- **CLAUDE.md** (between markers only) — the map
- **rules/conventions.md** — overrides-only conventions
- **rules/risk-rules.md** — structured risk classification
- **rules/workflow.md** — session protocol
- **rules/architecture.md** — non-obvious architecture decisions
- **hooks/pre-command.sh** — risk classifier hook
- **hooks/post-edit.sh** — auto-formatter hook

### Zone B — Agent-Managed

Files in `state/`. Created once by toolkit, then owned by the AI agent. Toolkit never overwrites.

- **state/progress.md** — session continuity
- **state/learnings.md** — discovered gotchas
- **state/plans/*.md** — work plans (from templates)

## CLAUDE.md Format — v2 Map

### Structure

```markdown
<!-- HARNESS:START v2 — Auto-generated by harness-toolkit v0.1.0. Do not edit. -->

# Harness · project-name · standard tier

TypeScript · Next.js 15 · pnpm · Vitest · Vercel · Supabase

## Rules
- Read `.claude/harness/rules/conventions.md` before writing code
- Read `.claude/harness/rules/risk-rules.md` before running commands
- Follow session protocol in `.claude/harness/rules/workflow.md`
- Pre-command hook enforces risk rules automatically

## State
- `.claude/harness/state/progress.md` — read at start, update at end
- `.claude/harness/state/plans/` — active work plans

## Critical (always in context)
- Use `pnpm`, never `npm` or `yarn`
- Run `pnpm check` before committing (lint + type-check + test)
- Never modify files in `packages/legacy/` — scheduled for removal

<!-- HARNESS:END v2 -->
```

### Properties

- **~20 lines** — fits comfortably in L1 context
- **Map, not content** — pointers to files, not the content itself
- **Critical rules inline** — 3-5 most important rules always in context
- **Stack summary** — one line, agent knows what it's working with
- **v2 markers** — `<!-- HARNESS:START v2 -->` and `<!-- HARNESS:END v2 -->`
- **User content outside markers is untouched**

## Tier Output Comparison

| File | Minimal | Standard | Full | Enterprise |
|---|---|---|---|---|
| CLAUDE.md (map) | Yes | Yes | Yes | Yes |
| rules/conventions.md | Yes | Yes | Yes (evaluated) | Yes (evaluated) |
| rules/risk-rules.md | Yes | Yes | Yes (evaluated) | Yes (evaluated) |
| rules/workflow.md | No | Yes | Yes | Yes |
| rules/architecture.md | No | No | Yes (evaluated) | Yes (evaluated) |
| hooks/pre-command.sh | Yes | Yes | Yes | Yes |
| hooks/post-edit.sh | No | If formatter detected | If formatter detected | If formatter detected |
| state/progress.md | No | Yes | Yes | Yes |
| state/learnings.md | No | Yes | Yes | Yes |
| state/plans/ templates | No | Yes | Yes | Yes |
| config.json | Yes | Yes | Yes | Yes |
| project-context.json | Yes | Yes | Yes | Yes |

"Evaluated" = passed through generator-evaluator loop (max 2 iterations).
