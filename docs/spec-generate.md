## Zone A: LLM-Generated Content

### `rules/conventions.md` — Overrides Only

#### Prompt template: `prompts/generate/conventions.md.tmpl`

```markdown
You are generating coding conventions for a CLAUDE.md harness file.

## Project Context
```json
{{project_context_json}}
```

## CRITICAL RULE: Overrides Only

You are generating conventions for an AI agent (Claude Code) that ALREADY KNOWS:
- Standard conventions for {{stack.frameworks}} (naming, file structure, patterns)
- How to read package.json, tsconfig.json, eslint config
- Default testing patterns for {{stack.test_framework}}
- Standard import ordering, formatting rules

DO NOT include any of the above. The agent discovers these by reading the code.

ONLY output conventions that:
1. **Override defaults** — "Use snake_case for API routes" (agent would default to camelCase)
2. **Are team-specific** — "Use pnpm, never npm" (agent can't know team preference)
3. **Are counter-intuitive** — "Never use barrel exports" (agent would create them)
4. **Reference project-specific utilities** — "Use Result<T,E> from lib/result.ts" (agent can't guess this exists)
5. **Document known gotchas** — "packages/ui has peer dep on React 18, don't upgrade"

## Output Format

Output pure markdown. Structure:

```markdown
## Conventions — Overrides & Non-Obvious

### Code Style Overrides
[rules that override standard conventions for this stack]

### Testing
[testing-specific rules, helper references, forbidden patterns]

### Patterns to Follow
[project-specific patterns, utility references]

### Known Gotchas
[dependency issues, compatibility notes, things that will break]
```

Each section should have 2-5 bullet points. If a section would be empty, omit it entirely.
Target: 20-40 lines total. Every line must change agent behavior.
```

### `rules/risk-rules.md` — Structured Format

#### Prompt template: `prompts/generate/risk-rules.md.tmpl`

```markdown
You are generating command risk classification rules for an AI agent harness.

## Project Context
```json
{{project_context_json}}
```

## Stack-Specific Context
- Package manager: {{stack.package_manager}}
- Database: {{infrastructure.database}}
- Deployment: {{infrastructure.deployment}}
- CI/CD: {{infrastructure.ci_cd}}
- Has agents: {{ai_indicators.has_agents}}

## Output Format

Output exactly this structure. Each rule is one line. Be specific to THIS project's stack.

```markdown
## Risk Classification

### Blocked (never run, hook exits 2)
[commands that should NEVER be run by agent — destructive, irreversible]

### Risky (confirm first, hook exits 1)
[commands that need human approval — deploys, pushes, migrations]

### Safe (auto-approved)
[commands that are always safe to run — tests, linting, status checks]
```

## Rules for generation
- Use actual command names from this project (e.g., `pnpm test` not `npm test`)
- Include database-specific commands if database detected
- Include deployment-specific commands if deployment detected
- Include package manager-specific commands
- Each category should have 3-8 rules
- Format: `command or pattern` — brief explanation
```

## Template

Generate the protocol by filling in project-specific values. Use actual commands and file paths.

```markdown
## Session Protocol

### 1. Orient (every new session)
- Read `.claude/harness/state/progress.md`
- Read active plan in `.claude/harness/state/plans/` if one exists
- `git log --oneline -10`
- Check for broken state: `{{verify_command}}`

### 2. Plan (before coding)
- If starting new work: create plan from template in `state/plans/`
- If continuing work: read existing plan, check off completed steps
- Scope to ONE task. If task is big, break it down in the plan first.

### 3. Execute (while coding)
- Make changes incrementally
- Run relevant tests after each change: `{{test_command}}`
- If you discover a bug unrelated to current work: note in `state/learnings.md`, don't fix now

### 4. Verify (before committing)
- `{{verify_command}}`
- For UI changes: verify in browser, check for console errors
- For API changes: test with actual requests

### 5. Wrap Up (end of session or end of task)
- Commit with descriptive message
- Update plan: check off completed steps
- Update `state/progress.md`: what done, what's next, any issues
- If you learned something non-obvious: add to `state/learnings.md`
```

Replace placeholders:
- `{{verify_command}}`: The project's full check command (e.g., `pnpm check`, `go test ./...`, `pytest`)
- `{{test_command}}`: The project's targeted test command (e.g., `pnpm test -- --filter`, `go test`)

### Critical Rules — Inline in CLAUDE.md

#### Prompt template: `prompts/generate/critical-rules.md.tmpl`

```markdown
You are selecting 3-5 critical rules to be placed inline in CLAUDE.md (always in agent context).

## Project Context
```json
{{project_context_json}}
```

## Selection Criteria

A critical rule must meet ALL THREE:
1. **High-damage if violated** — data loss, production break, security breach
2. **Counter-intuitive** — an AI agent would do the opposite by default
3. **Frequent** — likely to come up in most sessions

## Examples

GOOD critical rules:
- "Use `pnpm`, never `npm` or `yarn`" — agents default to npm
- "Never modify files in `packages/legacy/` — scheduled for removal"
- "Run `pnpm check` before committing (lint + type-check + test)"
- "Supabase migrations require manual review — never auto-apply"
- "Never commit .env files — use .env.example for templates"

BAD critical rules (don't include):
- "Use TypeScript" — obvious from tsconfig.json
- "Write tests" — too generic, not specific enough
- "Follow code style" — that's what conventions.md is for
- "Use React" — obvious from package.json

## Output Format

Output ONLY a markdown list of 3-5 rules. No headers, no explanations.
Each rule: `- [rule text]`

```markdown
- Use `pnpm`, never `npm` or `yarn`
- Never modify files in `packages/legacy/` — scheduled for removal
- Run `pnpm check` before committing (lint + type-check + test)
```
```

## Generator-Evaluator Loop (Full+ Tier)

The evaluator runs on LLM-generated Zone A content to ensure quality. Only for `rules/conventions.md`, `rules/risk-rules.md`, and `rules/architecture.md`.

### Evaluator Prompt: `prompts/evaluator.md.tmpl`

```markdown
You are evaluating generated harness content for an AI agent.

## Project Context
```json
{{project_context_json}}
```

## Generated Content
```markdown
{{generated_content}}
```

## File: {{file_name}}

## Evaluation Criteria

1. **SPECIFICITY**: Is every rule specific to this project?
   FAIL: "Use meaningful variable names" (generic, agent already knows)
   PASS: "API routes use snake_case (legacy compat)" (specific, agent doesn't know)

2. **DISCOVERABILITY**: Can this rule be discovered from reading code?
   FAIL: "Use TypeScript" (agent sees tsconfig.json)
   PASS: "Never use barrel exports" (agent can't know team policy)

3. **ACTIONABILITY**: Can the agent follow this mechanically?
   FAIL: "Write clean, maintainable code" (vague, useless)
   PASS: "Use Result<T,E> from lib/result.ts instead of try/catch" (exact, actionable)

4. **CONCISENESS**: Is the file under 40 lines?
   If over 40 lines → identify generic items to cut

## Output Format

```json
{
  "pass": true|false,
  "issues": [
    {
      "line": "quoted line from content",
      "problem": "specificity|discoverability|actionability|conciseness",
      "suggestion": "what to do instead"
    }
  ],
  "summary": "brief assessment"
}
```

If pass=true, issues should be empty. If pass=false, list the specific lines that need fixing.
```

### Evaluator Execution

```bash
run_evaluator() {
  local file="$1"
  local file_name="$(basename "$file")"
  local content="$(cat "$file")"
  local context_file="$PROJECT_ROOT/.claude/harness/project-context.json"
  local max_iterations=2
  local iteration=0

  while [ "$iteration" -lt "$max_iterations" ]; do
    iteration=$((iteration + 1))

    # Build evaluator prompt
    local prompt="$(resolve_template "$TOOLKIT_DIR/prompts/evaluator.md.tmpl" "$context_file")"
    prompt="$(echo "$prompt" | sed "s|{{generated_content}}|$(echo "$content" | head -60)|")"
    prompt="$(echo "$prompt" | sed "s|{{file_name}}|$file_name|")"

    local response="$(call_llm "$prompt")"
    local pass="$(echo "$response" | jq -r '.pass')"

    if [ "$pass" = "true" ]; then
      log_step "  Evaluator: $file_name passed (iteration $iteration)"
      return 0
    fi

    log_step "  Evaluator: $file_name needs revision (iteration $iteration)"
    local issues="$(echo "$response" | jq -r '.issues[] | "  - [\(.problem)] \(.line) → \(.suggestion)"')"
    log_verbose "$issues"

    # Re-generate with feedback
    if [ "$iteration" -lt "$max_iterations" ]; then
      local regen_prompt="Revise the following content based on evaluator feedback.

Original content:
\`\`\`markdown
$content
\`\`\`

Issues found:
$issues

Fix ONLY the identified issues. Keep everything else unchanged.
Output the revised markdown content only."

      content="$(call_llm "$regen_prompt")"
      echo "$content" > "$file"
    fi
  done

  log_warn "  Evaluator: $file_name accepted with warnings after $max_iterations iterations"
  return 1
}
```

## CLAUDE.md Map Assembly (Template, No LLM)

The CLAUDE.md map is assembled from template + generated critical rules. No LLM needed for the map itself.

```bash
assemble_map_content() {
  local config_file="$PROJECT_ROOT/.claude/harness/config.json"
  local context_file="$PROJECT_ROOT/.claude/harness/project-context.json"
  local critical_rules_file="$PROJECT_ROOT/.claude/harness/rules/.critical-rules.tmp"

  local project_name="$(json_get "$context_file" ".project.name")"
  local tier="$(json_get "$config_file" ".tier")"

  # Build stack summary line
  local languages="$(json_get "$context_file" ".stack.languages | join(\", \")")"
  local frameworks="$(json_get "$context_file" ".stack.frameworks | join(\", \")")"
  local pkg_manager="$(json_get "$context_file" ".stack.package_manager")"
  local test_fw="$(json_get "$context_file" ".stack.test_framework")"
  local deployment="$(json_get "$context_file" ".infrastructure.deployment")"
  local database="$(json_get "$context_file" ".infrastructure.database")"

  local stack_parts=""
  [ -n "$languages" ] && stack_parts="$languages"
  [ -n "$frameworks" ] && stack_parts="$stack_parts · $frameworks"
  [ "$pkg_manager" != "unknown" ] && stack_parts="$stack_parts · $pkg_manager"
  [ -n "$test_fw" ] && stack_parts="$stack_parts · $test_fw"
  [ "$deployment" != "none" ] && stack_parts="$stack_parts · $deployment"
  [ "$database" != "none" ] && stack_parts="$stack_parts · $database"

  # Build map
  local map="# Harness · $project_name · $tier tier

$stack_parts

## Rules
- Read \`.claude/harness/rules/conventions.md\` before writing code
- Read \`.claude/harness/rules/risk-rules.md\` before running commands"

  # Add workflow pointer for standard+ tier
  if [ "$tier" != "minimal" ]; then
    map="$map
- Follow session protocol in \`.claude/harness/rules/workflow.md\`"
  fi

  # Add architecture pointer for full+ tier
  local tier_level="$(tier_to_level "$tier")"
  if [ "$tier_level" -ge 3 ]; then
    map="$map
- Read \`.claude/harness/rules/architecture.md\` for non-obvious design decisions"
  fi

  map="$map
- Pre-command hook enforces risk rules automatically"

  # Add state section for standard+ tier
  if [ "$tier" != "minimal" ]; then
    map="$map

## State
- \`.claude/harness/state/progress.md\` — read at start, update at end
- \`.claude/harness/state/plans/\` — active work plans"
  fi

  # Add critical rules (generated by LLM)
  if [ -f "$critical_rules_file" ]; then
    map="$map

## Critical (always in context)
$(cat "$critical_rules_file")"
  fi

  echo "$map"
}

## Full Generation Orchestration

```bash
run_generate() {
  local context_file="$PROJECT_ROOT/.claude/harness/project-context.json"
  local config_file="$PROJECT_ROOT/.claude/harness/config.json"
  local tier="$(json_get "$config_file" ".tier")"
  local tier_level="$(tier_to_level "$tier")"
  local rules_dir="$PROJECT_ROOT/.claude/harness/rules"
  local state_dir="$PROJECT_ROOT/.claude/harness/state"

  mkdir -p "$rules_dir" "$state_dir/plans"

  # --- Zone A: LLM-generated rules ---

  # All tiers: conventions + risk-rules + critical-rules
  log_step "Generating conventions.md..."
  generate_from_template "conventions" "$context_file" "$rules_dir/conventions.md"

  log_step "Generating risk-rules.md..."
  generate_from_template "risk-rules" "$context_file" "$rules_dir/risk-rules.md"

  log_step "Generating critical rules..."
  generate_from_template "critical-rules" "$context_file" "$rules_dir/.critical-rules.tmp"

  # Standard+: workflow (session protocol)
  if [ "$tier_level" -ge 2 ]; then
    log_step "Generating workflow.md (session protocol)..."
    generate_from_template "workflow" "$context_file" "$rules_dir/workflow.md"
  fi

  # Full+: architecture
  if [ "$tier_level" -ge 3 ]; then
    log_step "Generating architecture.md..."
    generate_from_template "architecture" "$context_file" "$rules_dir/architecture.md"
  fi

  # --- Evaluator loop (full+ tier only) ---
  if [ "$tier_level" -ge 3 ]; then
    log_step "Running evaluator..."
    run_evaluator "$rules_dir/conventions.md"
    run_evaluator "$rules_dir/risk-rules.md"
    run_evaluator "$rules_dir/architecture.md"
  fi

  # --- Zone A: Deterministic hooks ---
  log_step "Generating hooks..."
  generate_hooks "$context_file" "$tier"

  # --- Zone B: Static templates (only if not already existing) ---
  if [ "$tier_level" -ge 2 ]; then
    write_zone_b_if_missing "$state_dir"
  fi

  # --- CLAUDE.md map (template, no LLM) ---
  log_step "Assembling CLAUDE.md map..."
  local map_content="$(assemble_map_content)"
  echo "$map_content" > "$PROJECT_ROOT/.claude/harness/.map-content.tmp"

  log_success "Generation complete"
}

# Generate content from prompt template + project context
generate_from_template() {
  local template_name="$1"
  local context_file="$2"
  local output_file="$3"

  local prompt="$(resolve_template "$TOOLKIT_DIR/prompts/generate/${template_name}.md.tmpl" "$context_file")"
  local content="$(call_llm "$prompt")"
  echo "$content" > "$output_file"
}

# Write Zone B templates only if they don't already exist (agent owns these)
write_zone_b_if_missing() {
  local state_dir="$1"

  if [ ! -f "$state_dir/progress.md" ]; then
    cp "$TOOLKIT_DIR/templates/zone-b/progress.md" "$state_dir/progress.md"
    log_step "  Created state/progress.md"
  fi

  if [ ! -f "$state_dir/learnings.md" ]; then
    cp "$TOOLKIT_DIR/templates/zone-b/learnings.md" "$state_dir/learnings.md"
    log_step "  Created state/learnings.md"
  fi

  if [ ! -f "$state_dir/plans/_template-feature.md" ]; then
    cp "$TOOLKIT_DIR/templates/zone-b/_template-feature.md" "$state_dir/plans/_template-feature.md"
    log_step "  Created state/plans/_template-feature.md"
  fi

  if [ ! -f "$state_dir/plans/_template-bugfix.md" ]; then
    cp "$TOOLKIT_DIR/templates/zone-b/_template-bugfix.md" "$state_dir/plans/_template-bugfix.md"
    log_step "  Created state/plans/_template-bugfix.md"
  fi
}

## Selective Generation (for `harness update`)

When updating, only regenerate what's needed based on context changes.

```bash
run_selective_generate() {
  local tier="$1"
  local context_file="$PROJECT_ROOT/.claude/harness/project-context.json"
  local old_context="$PROJECT_ROOT/.claude/harness/backup/latest/project-context.json"

  # Compare sections to determine what changed
  local changed_sections=""

  for section in stack infrastructure shape ai_indicators conventions; do
    local old="$(jq ".$section" "$old_context" 2>/dev/null)"
    local new="$(jq ".$section" "$context_file" 2>/dev/null)"
    if [ "$old" != "$new" ]; then
      changed_sections="$changed_sections $section"
    fi
  done

  if [ -z "$changed_sections" ]; then
    log_step "No content-affecting changes detected. Skipping generation."
    return
  fi

  log_step "Changed sections:$changed_sections"

  # Regenerate affected files
  # stack/conventions change → regenerate conventions.md + critical-rules
  echo "$changed_sections" | grep -q "stack\|conventions" && \
    generate_from_template "conventions" "$context_file" "$PROJECT_ROOT/.claude/harness/rules/conventions.md"

  # infrastructure change → regenerate risk-rules.md
  echo "$changed_sections" | grep -q "infrastructure" && \
    generate_from_template "risk-rules" "$context_file" "$PROJECT_ROOT/.claude/harness/rules/risk-rules.md"

  # Any change → regenerate critical rules + map
  generate_from_template "critical-rules" "$context_file" "$PROJECT_ROOT/.claude/harness/rules/.critical-rules.tmp"

  # Always reassemble map
  local map_content="$(assemble_map_content)"
  echo "$map_content" > "$PROJECT_ROOT/.claude/harness/.map-content.tmp"
}
```

## Hook Generation (Deterministic)

```bash
generate_hooks() {
  local context_file="$1"
  local tier="$2"
  local hooks_dir="$PROJECT_ROOT/.claude/harness/hooks"
  local tier_level="$(tier_to_level "$tier")"

  mkdir -p "$hooks_dir"

  # All tiers: pre-command risk classifier
  local risk_rules="$PROJECT_ROOT/.claude/harness/rules/risk-rules.md"
  generate_pre_command_hook "$risk_rules" "$hooks_dir/pre-command.sh"
  chmod +x "$hooks_dir/pre-command.sh"

  # Standard+: post-edit auto-format
  if [ "$tier_level" -ge 2 ]; then
    local formatter="$(json_get "$context_file" ".stack.formatter")"
    if [ "$formatter" != "none" ]; then
      generate_post_edit_hook "$formatter" "$hooks_dir/post-edit.sh"
      chmod +x "$hooks_dir/post-edit.sh"
    fi
  fi
}

# Parse risk-rules.md to generate pre-command hook
generate_pre_command_hook() {
  local rules_file="$1"
  local output="$2"

  local blocked_patterns=""
  local risky_patterns=""

  # Extract patterns from structured risk-rules.md
  local section=""
  while IFS= read -r line; do
    case "$line" in
      "### Blocked"*) section="blocked" ;;
      "### Risky"*)   section="risky" ;;
      "### Safe"*)    section="safe" ;;
      "- "*)
        local pattern="$(echo "$line" | sed 's/^- `\([^`]*\)`.*/\1/' | sed 's/^- //')"
        case "$section" in
          blocked) blocked_patterns="$blocked_patterns|$pattern" ;;
          risky)   risky_patterns="$risky_patterns|$pattern" ;;
        esac
        ;;
    esac
  done < "$rules_file"

  # Remove leading pipe
  blocked_patterns="$(echo "$blocked_patterns" | sed 's/^|//')"
  risky_patterns="$(echo "$risky_patterns" | sed 's/^|//')"

  cat > "$output" << 'HOOK_EOF'
#!/bin/sh
# [harness] Risk classification hook
# Auto-generated — will be overwritten on `harness update`

COMMAND="$1"

HOOK_EOF

  if [ -n "$blocked_patterns" ]; then
    cat >> "$output" << EOF
# Blocked patterns
case "\$COMMAND" in
  $( echo "$blocked_patterns" | tr '|' '\n' | sed 's/.*/*&*/' | paste -sd'|' - ))
    echo "BLOCKED: Dangerous command detected"
    exit 2
    ;;
EOF
  fi

  if [ -n "$risky_patterns" ]; then
    cat >> "$output" << EOF
  $( echo "$risky_patterns" | tr '|' '\n' | sed 's/.*/*&*/' | paste -sd'|' - ))
    echo "RISKY: Requires confirmation"
    exit 1
    ;;
EOF
  fi

  cat >> "$output" << 'HOOK_EOF'
  *)
    exit 0
    ;;
esac
HOOK_EOF
}
```

## Edge Cases

| Case | Handling |
|---|---|
| LLM generates > 40 lines for a rules file | Evaluator flags conciseness, requests trim (full+ tier). For minimal/standard tier, accept with warning. |
| LLM returns non-markdown | Wrap in markdown. If totally garbled, retry once. |
| LLM timeout during generation | Retry once. On second failure, exit 5. |
| LLM timeout during evaluation | Skip evaluation, accept content with warning. |
| Zone B files already exist (from previous init) | Never overwrite. Log "state/progress.md already exists (agent-managed, skipping)". |
| Critical rules LLM returns > 5 rules | Take first 5 only. |
| Critical rules LLM returns < 3 rules | Accept as-is (some projects genuinely have fewer critical rules). |
| Project with no test framework | Workflow template uses "run relevant tests" instead of specific command. |
| Evaluator loop: still failing after 2 iterations | Accept with warning. Log which criteria failed. |
| `harness update` with only Zone B changes | No regeneration needed. Zone B is agent-managed. |
